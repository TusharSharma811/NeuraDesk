[08:30 AM] ME:
I'm working on the HackerRank Orchestrate hackathon. The challenge is to build 
an AI-powered support ticket triage agent that can process customer support 
tickets for three companies — HackerRank, Claude (Anthropic), and Visa.

Here's the problem: We're given 29 support tickets in a CSV file and a corpus 
of support documentation under data/ (organized by company). The agent needs to:
  1. Read each ticket
  2. Retrieve relevant documentation from the corpus
  3. Classify the ticket (status, product_area, request_type)
  4. Generate a grounded response using ONLY the corpus docs
  5. Output everything to a CSV

The evaluation criteria are: agent design, output quality, and AI fluency.

[08:32 AM] ME:
Here's my architectural plan. I want a modular pipeline with clear separation 
of concerns:

  1. INDEXER (indexer.py)
     - Chunk all markdown docs from data/ into passages
     - Build a vector index using sentence-transformers embeddings
     - Cache the index to disk so we don't rebuild every run

  2. RETRIEVER (retriever.py)  
     - Hybrid retrieval: combine BM25 (keyword) + dense vector search
     - Add a cross-encoder reranker (ms-marco-MiniLM-L-6-v2) on top 
       for better precision
     - Filter by company name so we only retrieve docs from the right 
       product ecosystem

  3. CLASSIFIER (classifier.py)
     - Pre-classify tickets using rule-based heuristics before hitting 
       the LLM — things like detecting billing keywords, security 
       issues, out-of-scope requests
     - This gives the LLM additional guidance and reduces hallucination

  4. AGENT (agent.py)
     - Build structured prompts with system instructions, retrieved 
       context, and the ticket text
     - Call the LLM and parse JSON output
     - Multi-provider support: Gemini as primary, Groq as fallback
     - Strict escalation rules for high-risk tickets (billing, fraud, 
       identity theft, score disputes)

  5. MAIN (main.py)
     - Orchestrate the full pipeline end-to-end
     - Handle rate limiting for API-based providers
     - CLI interface with provider selection

  Key design decisions:
  - RAG over fine-tuning: We need grounded responses, not memorized ones
  - Hybrid retrieval over pure vector search: BM25 catches exact keyword 
    matches that embeddings miss (like order IDs, product names)
  - Cross-encoder reranking: Significantly improves retrieval precision 
    at minimal latency cost
  - Structured JSON output: Forces the LLM into a predictable schema
  - Escalation-first safety: When in doubt, escalate to a human agent
